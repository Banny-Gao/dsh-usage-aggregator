# ADR 0004 · 设置面板只占一个入口

- **状态**：已采纳
- **日期**：2026-10-30

## 背景

迁移前，设置面板里有两个来自这三个插件的入口：

- `settings.section` id `usage-query`（order 92）—— 用量查询
- `settings.section` id `axzo-theme`（order 93）—— 品牌主题

插件页里还有一个 `plugins.tab` id `updates`（order 20）—— 插件更新。

收拢的核心理由之一是：**「每新增一个插件，设置面板就会多一个入口」**。如果合并后仍然注册两个 `settings.section`，这个理由就只兑现了一半。

## 决策

**只注册一个 `settings.section`**（id `usage-aggregator`，order 92），内容是一个页签条 + 当前功能的视图：

```
设置 → AxzoAggregator
        [ Theme ] [ 流量 ] [ 插件更新 ]
```

三个功能各自提供 `HubView`，页签标签取自**聚合页自己的**命名空间（`meta.hubTabKey` 指向 `src/client/hub/i18n.js` 里的键）。不放进各功能的 locale 命名空间：同一个命名空间同时只能被一个包注册，新旧插件并存时功能探不到自己的字典，页签上会显示裸的 key 名。

「插件更新」是**默认选中**的页签（`meta.hubDefault`）—— 打开设置页就先自动检测有哪些插件能升级。

**插件页的 `plugins.tab`（id `updates`）保留原位** —— 它不在设置面板里，而在「插件」页上，是那个页面的自然归宿（官方 marketplace 也在同一组 tab 里）。

## 理由

- **直接兑现用户诉求**：设置面板从两个入口变一个；以后加功能只多一个页签，不多一个入口。
- **插件管理器同样只占一行**：这才是「一个插件」在 DSH 里的完整含义。
- **`plugins.tab` 保留**：它在另一个页面上，且是「发现并管理插件」这条工作流的自然落点 —— 删掉它会丢能力。
- **页签标签来自各自命名空间**：切换语言时标签跟着各自字典走，不引入第四份翻译。

## 后果

- **两个页签会渲染在同一个页面里**：三个功能的视图此前各自独立成页，现在要能在同一个内容列里共存。要求：各功能的样式自带作用域（用量查询用 `duq-` 前缀、插件更新用 `dpe-` 前缀，主题用 `dsh-axzo-*` 前缀 —— 三者互不冲突）；主题的 `<style>` 是 head 级全局注入（本来就该全局），另两个是随组件渲染。
- **页签切换是组件内的 state**：槽位注册的渲染函数每次渲染都新建组件实例，state 必须挂在组件上，不能挂在 `apply()` 里（Hook 在那里调用会直接崩）。三个功能原本各自遵守这条，合并后沿用。
- **主题的设置页从前是独立页面**，现在在页签里 —— 它的预览区宽度受内容列限制。实现时若发现布局被压扁，需要在该功能内调整。

## 备选方案

- **保留两个 `settings.section`**：改动最小，但没兑现「设置面板一个入口」的目标。放弃。
- **把插件更新也做成设置页里的页签，且不再注册 `plugins.tab`**：设置面板里更整齐，但「插件」页上就没有更新入口了 —— 那是能力损失。放弃。
