# 钉钉沙发 · 在会话里发钉钉消息

这个技能管两件事：**提议一次外发**（发消息），和**读懂一条钉钉新消息**（收消息）。
两边都有硬规矩 —— 外发必须由用户点按钮确认，收消息只分析不动手。

## 一、发消息

### 什么时候提议

- 用户明确说了要把内容发给某人：「把这段发给陈世康」「同步给后端」「把这个结论告诉 XXX」。
- 上一轮已经解析过收件人，用户这次只说「发给后端」—— 复用上一轮解析到的标识，
  但**照样要走卡片确认**。
- 你刚做完一个结论，判断它值得让某个人知道 —— 由你判断，插件不替你判断值不值得发。

### 流程（顺序不能乱）

1. **定收件人**。用户给了姓名就用姓名；只知道「后端」这种指代时，先在会话里找
   有没有已经解析过的人；没有就调 `dingtalk_find` 解析。
2. **多人同名要停**。`dingtalk_find` 返回多个候选时，**不要挑第一个**：把候选
   （姓名 + 标识片段）列给用户选，拿到选择再继续。
3. **写正文**（你写，不要贴聊天记录）。默认结构：
   - 结论先行（一句话说清结果）；
   - 复现步骤（对方要能照着做）；
   - 期望 / 实际；
   - 需要对方确认什么。
   正文超过 5000 字要拆成几条，或者改成发一个文档链接。
4. **提议一次外发**——调 `propose_action`：

   ```
   action: "dingtalk.send"
   title:  一句话说清发什么
   brief:  为什么发给他（用用户的语言）
   details: {
     recipient:    "陈世康",          // 姓名，回显用
     recipientId: "…",               // 解析到的标识（有就带上，省一次通讯录查询）
     channel:      "dm",              // 单聊 dm；群聊 group（群发必须写清 @ 谁）
     reason:       "他负责后端接口，这版改动要他确认",
     body:         "……拟好的正文……"
   }
   ```

5. **到此为止**。用户会在卡片上点【发送】/【改一下】/【不用了】。
   你**不能**自己发出去，也不要说「已经发给你了」这类话。

### 卡片上的三个按钮意味着什么

- **发送** —— 插件真的发，并回查真实的消息 ID。回查不到时卡片显示
  「已提交，未确认送达」，这时候要照实说「发出去了但没确认到送达」，不要说成已送达。
- **改一下** —— 你会收到一条注入的提示（原文 + 用户的修改要求）。按它重写正文，
  然后**重新**调一次 `propose_action` 出新卡片；用户在新卡片上再点一次【发送】。
- **不用了** —— 结束这件事，不要再提。

## 二、收到钉钉消息

插件判断一条消息跟当前项目有关时，会把「消息原文 + 来源 + 当前会话在做什么」
一起注入给你。这时**只做分析，不要动手**：

- 产出三段：① 这条消息在说什么（摘要）② 它和当前项目的关系 ③ 建议我做什么；
- 然后用 `ask_user_question` 问用户要不要处理（选项：处理 / 忽略 / 改成……）；
- 用户点「处理」之前：不要查代码、不要调接口、不要起草回复、不要发钉钉。

用户问「钉钉有什么新消息」时，用 `dingtalk_read` 拉一份清单（只读）。

## 三、硬规矩

- **不猜收件人**。任何回显都带「姓名 + 唯一标识片段」，避免同名发错人。
- **不绕过卡片**。发送只发生在用户点【发送】的时候。
- **不主动转发、不群发、不定时发**。
- 项目外的钉钉消息插件只会累一个未读计数，不会来打扰你 —— 别自己去翻消息列表。
