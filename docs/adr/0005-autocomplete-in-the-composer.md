# ADR 0005 · 自动补全落在输入框，且不改别人的节点

- **状态**：已采纳
- **日期**：2026-11-03

## 背景

需求是「自动分析上下文并在对话框中进行自动补全」：给对话输入框加上
placeholder 提示、Tab 补全、下拉列表，以及一批可配置项。

动手前要先回答三个问题：

1. **「对话框」是哪一个？** 本插件已有的面板输入框（粘 cURL 的那个）还是
   DSH 的**会话输入框**？只有后者有「他下一句想说什么」这个上下文。
2. **会话输入框能不能改？** 它是 `ui-conversation` 拥有的：编辑器是 Lexical 的
   `contenteditable`，草稿在输入机里，placeholder 由官方组件渲染。
   客户端插件**没有**「编辑器内部」的槽位 —— 官方 103 个槽位里没有一个渲染在
   编辑器里面。
3. **Tab 键归谁？** 官方的 `/`、`@` 菜单已经用 Tab 选中菜单项。

## 决策

**做在 DSH 的会话输入框上，只用官方槽位，不改别人的节点与样式。**

| 落点 | 槽位 | 放什么 |
|---|---|---|
| 输入框**上方** | `conversation.input.dock`（list · 会话级） | 提示条：第一条建议 + 「Tab 补全」+ 「更多」 |
| 输入框**卡片内** | `conversation.input.overlay`（list · 会话级） | 下拉列表 + 行内灰字（官方 `/`、`@` 菜单走的就是这一层） |

配套的三条规矩：

1. **不替换官方 placeholder**。「空输入时的占位提示」做在提示条上，不去动
   `[data-composer-placeholder]` —— 那是 `ui-conversation` 的，而且它还承载
   「无可用会话」「父会话离线」这些官方状态，顶掉就说错话了。
2. **不碰编辑器**。写回草稿只走官方标准动作
   `inputActions.captureInsertion()` + `insertText(text, span)`；行内灰字是
   **画在自己那一层**上的叠加（量光标位置定位），编辑器里一个节点都不插。
3. **Tab 只在合适的时候接管**：有候选、官方菜单没开、没有 IME 组合、输入机在
   `plain` 状态才拦；Shift+Tab 永不接管。

候选落进输入框时，求「草稿结尾」与「候选开头」的**最长重叠**，只插重叠之后的
那一段（模型给的是完整的一句话，用户已经打了半句）。

## 理由

- **会话输入框才是对的地方**：用户正在写字的那一刻，就是「他下一句想说什么」
  最清楚的时刻。别的落点没有这个上下文。
- **官方槽位是唯一稳的接缝**：`conversation.input.overlay` 官方自己就在用
  （命令菜单），跟着它走就不会撞上别人的布局；类名是构建期哈希（`uV2eYG_*`），
  只能用 `data-*` 定位。
- **不碰别人的东西**：这是客户端插件的硬规矩（`cordis-plugin-development` 的
  UI 约定）。往编辑器里插节点，Lexical 下一次更新就会抹掉，还可能跟它打架。
- **候选要有重叠**：直接插整句会得到「帮我分析帮我分析这段代码的性能瓶颈」。
  没有重叠就不自动插 —— 那时候候选与用户写的不是同一条句子，硬插只会得到怪话。
- **Tab 要让路**：官方菜单开着的时候抢 Tab，两个功能会互相打架。

## 后果

- **官方 placeholder 原样保留**：空输入时用户看到的是官方 placeholder 加上
  提示条上的一行「按 Tab 采纳第一条，或点开列表换一条」，不是灰字占位。
- **行内灰字是 best-effort**：光标位置量不到（某些浏览器在行尾给不出矩形）时
  就没有灰字，只剩提示条与下拉 —— 设置里可以单独关掉它。
- **每次触发都要花一次模型调用**：因此有最少触发字数、触发延迟、Host 侧缓存
  与掐旧请求四道闸；模型不可用时安静退成「没有建议」。
- **Tab 的行为依赖官方输入机的 phase**：输入机在 `adjudicating` / `claimed` /
  `submitting` 时不给建议也不接管 Tab —— 那些状态下草稿正在被裁决或提交。

## 备选方案

- **替换 `conversation.composer.bar`（single 槽）自己重写整个输入框**：能完全
  控制 placeholder 与编辑器，但要重做附件、模型选择、发送、队列… 得不偿失，
  而且会顶掉官方后续的改进。放弃。
- **用 DOM 直接改官方 placeholder 的文字**：能做到「真正的灰字占位」，但那是
  改别人的节点，且 React 下一次渲染就会把它写回去。放弃。
- **注册成官方的 input-trigger source**（`/`、`@` 那条管线）：那条管线只认
  `/` 与 `@` 两个触发字符，接不了「自由文本补全」。放弃。
